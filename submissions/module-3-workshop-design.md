# Module 3: Workshop Design

## Workshop introduction

Title: Preptember: Your First Steps Toward Open Source

Target audience: NJIT students who are curious about GitHub, open source, or Hacktoberfest but have little or no prior experience. This workshop is especially for first-time contributors, students from non-CS backgrounds, and people who want a gentle introduction before trying their first pull request.

Length: 90 minutes. That gives enough time to explain the basics, practice together, and leave with a clear next step without overwhelming attendees.

## Learning objectives

1. Attendees will be able to explain the purpose of GitHub issues, pull requests, and repositories in an open source workflow.
2. Attendees will be able to attempt a contribution to a beginner-friendly open source task.
3. Attendees will be able to open a practice pull request and describe the steps they took to contribute to a real project.

## Pain, Dream, Fix

Pain: Many students want to participate in open source but feel blocked by unfamiliar GitHub language, fear of making mistakes, or not knowing where to start.

Dream: Students want to leave the workshop confident enough to find a beginner-friendly issue, make a contribution, and understand what happens when they open a pull request.

Fix: This workshop breaks the process into small guided steps: understanding the parts of a repository, reading issues, choosing a task, making a change in a practice repository, and opening a pull request with support from facilitators and peers.

## Materials

- Slidedeck with simple visuals explaining repositories, issues, branches, and pull requests.
- A practice GitHub repository with a few beginner-friendly issues or tasks.
- One-page cheat sheet for GitHub terms and the workshop steps.
- Links to GitHub Docs for repositories, issues, pull requests, and Git basics.
- A short follow-up resource list for Hacktoberfest, beginner-friendly open source projects, and next steps.

## Activities

1. Welcome and framing: I will greet attendees, explain the purpose of the workshop, and briefly connect it to Preptember and Hacktoberfest. Attendees will introduce themselves with their name, major, and one thing they hope to learn.
2. Concept overview: I will walk through the basic structure of GitHub using simple examples and visuals. Attendees will learn what a repository is, how issues are used, what a pull request is, and why open source projects use these tools.
3. Guided walkthrough: I will demo the workflow in a practice repository, starting from reading an issue and ending with opening a pull request. Attendees will follow along on their own devices or in pairs.
4. Shared practice: Attendees will choose a practice issue, identify the files or changes they would make, and draft a short plan for their contribution. Facilitators will circulate and answer questions.
5. Build time: Attendees will make a small change in the practice repository, such as editing documentation, fixing a typo, or updating a file. The goal is not perfection; the goal is to experience the workflow end to end.
6. Pull request review: I will show how to write a clear pull request description and how to respond to feedback. Attendees will open a practice PR or simulate one if the repository setup requires it.
7. Wrap-up and next steps: I will summarize the workflow, share next-step resources, and point attendees to real beginner-friendly projects they can try after the workshop. We will end with a short reflection and feedback form.

## Assessment

Attendees will show mastery by producing a practice contribution plan and a pull request or pull request draft in the workshop repository. For the first learning objective, success means they can correctly explain the role of a repository, an issue, and a pull request in their own words. For the second, success means they can identify a realistic beginner task and describe the steps they would take to complete it. For the third, success means they can follow the workflow far enough to open a PR and explain what they would do next in a real project.

I would assess this informally by asking attendees to talk through their process, checking their practice PRs, and listening for whether they can connect each step to the larger open source workflow.

## Feedback

I will give learners quick verbal feedback during the workshop as they work through the practice repository, especially when they are choosing an issue or drafting a pull request. If needed, facilitators can also give brief written notes on their practice PRs so attendees know what they did well and what to improve next time.

To collect feedback from attendees, I will reserve the last five minutes for a short survey and a closing conversation. I want to ask what was clear, what felt confusing, and what topics they want in a follow-up session. If possible, I would also leave a feedback form open after the workshop so people who need more time can respond later.
