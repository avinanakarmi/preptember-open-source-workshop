# GitHub Cheat Sheet

A quick glossary of terms used during the Preptember workshop.

## Terms

- Repository (repo): a project's folder on GitHub, containing all its files and version history.
- Issue: a tracked task, bug report, or discussion topic tied to a repository.
- Branch: a separate line of development so you can make changes without affecting the main codebase.
- Commit: a saved snapshot of changes with a description of what changed.
- Fork: your own copy of someone else's repository, which you can freely edit.
- Pull request (PR): a request to merge changes from one branch (often on your fork) into another (often the original project).
- Merge: combining the changes from a pull request into the target branch.
- Clone: downloading a copy of a repository to your own computer.

## Workshop steps at a glance

1. Fork the practice repository.
2. Clone your fork to your computer.
3. Read a beginner-friendly issue and pick one to try.
4. Create a branch for your change.
5. Make a small edit (fix a typo, update a doc).
6. Commit and push your change.
7. Open a pull request describing what you did.
8. Respond to any feedback from reviewers.
